# SVMH site build-out — 40 missing routes

The nav on all four built pages promises a site that does not exist. Forty internal routes are linked and unbuilt. This plan closes them in the existing DNA theme, adds two motion moves that belong to this design language, and fixes a routing defect that is currently invisible to the test suite.

Five research lanes ran in parallel across two models before any of this was written. Every claim below was re-verified directly against the repo.

## The finding that reorders everything

Before adding pages, the routing has to be settled — because three of the four **already-built** pages return 404 at their own canonical URL.

<Callout id="routing-decision" tone="decision">

**Every route becomes `<route>/index.html`.** That is the only layout that resolves identically under `python3 -m http.server` (which `README.md:93` prescribes) and on Netlify, Cloudflare Pages, Vercel and GitHub Pages. A flat `eot-cranes.html` layout would work in production and 404 locally — the kind of split that hides for months.

Consequence: the three existing pages move to `<route>/index.html`. `tools/make_sitemap.py:31-33` and `test_seo.py:85-87` both strip only the `index.html` segment and leave a trailing slash, while canonicals are slash-less. Those two helpers need one shared normalisation step, or the sitemap tests go red on the first moved page.

</Callout>

## Scope: subpages, not subdomains

Resolved from evidence rather than assumption. Every canonical tag already declares a path on one host (`https://www.svind.co.in/eot-cranes/double-girder`), every nav href is root-absolute, and `00_PLAN/01_SITEMAP_IA.md:64` structures the whole IA as root-level pillars. Real subdomains would mean rewriting all 40 hrefs, splitting SEO authority across hosts, and duplicating the theme per host — against the grain of every artifact in the repo.

<Callout id="fixture-bomb" tone="risk">

**The fixture time bomb.** `test_structure.py:24` does `exp = expected.get(page, {})` and every fixture assertion is then guarded by `if exp:` at line 53. Add a page to `PAGES` without running `conftest.py --refresh` and its 8 fixture checks are **silently skipped** — the run stays green while coverage quietly drops. At 40 pages that is 320 checks that can vanish without a single red line. Build the gate before the pages, not after.

</Callout>

## Motion: two moves, both earned

The site has **zero `@keyframes`**. Nothing moves unbidden. Live travel maxes out at 8px, there is exactly one easing curve, and hover states are 160ms "and barely there" (`tokens.css:278`). Any animation has to respect that or it will read as bolted on.

Also relevant: ~27% of `site.js` never executes. `.reveal` (site.js:306), `data-count-to` (site.js:424) and `data-filter` (site.js:498) are bound in JS and emitted by **no page** — verified, 0 hits each. There is a fully built, contract-documented reveal system sitting switched off.

  columns={["Move", "What happens", "Cost", "Reduced motion"]}
  rows={[

Reads as a press laying ink, not a web fade.", "Compositor-only clip-path. ~25 lines JS reusing the existing observer shape.", "clip-path: none — final state is pixel-identical to today"],
    ["S4 panel deal-in", "The three-up row arrives by its 4px gutters opening left-to-right, navy panel landing last. Animating negative space — almost nobody does this.", "transform on 3 elements, 4px travel, inside the existing 1-8px vocabulary.", "transform: none; base.css:623 already zeroes the stagger delays"],
  ]}
/>

Both animate elements the design law names as signature moves (S1, S4), using the ornament the design law names as its ornament (clip, gutters). The knockout is `aria-hidden="true"` and `user-select: none`, so the headline move carries zero accessibility surface.

**Rejected, with reasons:** fade-up-on-scroll everything (that *is* `.reveal`, and four finished pages deliberately declined it); parallax hero (the stage band is a 3-layer overlap the render suite tests for collisions); counting numbers (the machinery exists, but the values include `M8`, `807` and `2006` — counting up to a standards code is absurd); any looping motion (would break the system's defining rule).

<Callout id="will-change" tone="risk">

**Fix the contradiction first.** `test_layout.py` now asserts `.dna-knockout--stage` carries no `will-change`, on the grounds that a permanent hint pins a compositor layer for decorative content. But `components.css:36` and `components.css:1829` both ship permanent `will-change` — and 1829 is on `.reveal`, a class no page emits, so it is pure cost. Activating the reveal system makes that hint live on every revealed element. Remove it in the same change, and generalise the test from one selector to all of `components.css` + `dna.css` with a documented exception list.

Where a compositor hint is genuinely wanted: add it in JS at animation start, remove it on `transitionend`. Promotion that lives exactly as long as the motion.

</Callout>

## Also worth fixing while here

Found during research, cheap, and larger levers than anything in this plan:

- **`base.css:1` imports Google Fonts via `@import`.** The critical path is document → `base.css` → Google CSS → WOFF2, four levels deep, with no `preconnect` or `preload` anywhere. The entire type system is Inter Tight and the knockout is 120–320px of it, so this gates the most visually dominant element on every page.
- **No `srcset`, no WebP/AVIF.** Band images are served at 1600px wide to phones.
- **Missing sitewide:** OpenGraph (0 tags), Twitter card (0), favicon (0), theme-color (0), `robots.txt` (absent, while 3 pages link `/sitemap.xml`).
- **Meta descriptions run 235–330 chars.** Google truncates around 155.
- **`COMPONENT_CONTRACT.md` is stale and actively misleading** — it names a superseded design doc as law and documents retired values, including `--color-white: #FCFBF8` "never `#FFFFFF`" when surface *is* pure white now. A builder following it would produce drift.
